Why the Mobile UI Solves the "Stalled Bot" Problem

Traditional job bots run invisibly in terminal windows. When a job portal asks a new question (e.g. "Notice period if serving?" or "Do you know gRPC?"), typical bots either crash, guess wildly (hallucination), or skip the job completely.

With this agent, your computer sends an interactive prompt to your phone. The LLM extracts the exact answer from your resume, and you simply tap "Approve" during your morning coffee.

Mobile Web Access

Zero Repetition Memory

Complete End-to-End Backend Sequence Flow

Exact trace of execution across Mobile Client, Go HTTP/SSE Gateway, Playwright Browser, LLM Reasoner, and SQLite.

01
Cron Scheduler Fires (09:00 Mon-Sat)
Go scheduler launches crawler.RunDailySession(). Loads portal_cookies.json via go-secrets-file-mounted and boots stealth Playwright browser.
02
Listing Ingestion & 70% Skill Matcher
Crawler queries saved searches. Deduplicates against SQLite (60-day window). Computes weighted score: $S = \frac{1.0 \times M_R + 0.3 \times M_P}{1.0 \times R + 0.3 \times P}$. Drops non-qualifying jobs ($S < 0.70$).
03
Questionnaire Encountered → 3-Tier Resolution
DOM form inputs detected. Tier 1: Auto-fills CTC & notice period. Tier 2: Unmatched questions routed to LLM with candidate resume context.
04
Human Escalation via SSE Stream (Tier 3)
If question confidence < 85%, Go backend broadcasts AWAITING_USER_INPUT over Server-Sent Events (SSE). Mobile UI displays the interactive card.
05
Mobile User Approval & Final Apply
Candidate taps "Approve" → POST /api/v1/queue/:id/approve. Crawler injects answer, waits Gaussian delay (8-25s), clicks Submit, and records entry to SQLite.
